## 9월 14일 사용자 피드백 수정

- 캐릭터를 하나의 얼굴창·옆면 관절·등의 가방이 보이는 옆모습으로 다시 그렸습니다. 지면을 딛는 구간과 발을 들어 회수하는 구간을 분리했습니다. 좌우 방향·점프·낙하·완주 자세를 브라우저에서 확인했습니다.
- 10개 맵에 서로 다른 장애물 순서를 지정했습니다. 가장 짧은 45초 설정에도 갈라진 다리, 리듬문, 높낮이, 좌우 이동 발판, 승강석, 컨베이어가 포함됩니다.
- 연습에서 완주 판정이 제외되어 있었던 조건을 고쳤습니다. 기록을 확정하고 달리기를 멈추며, 완주 안내와 다음 맵·재도전·맵 선택 버튼을 표시합니다. 온라인은 서버 확정 기록으로 개인 안내 후 관전하고, 생존은 원래 규칙대로 계속 진행합니다.
- 수정 후 자동 검사 18개와 배포 빌드가 통과했습니다. 실제 공통 물리 자동 입력으로 30개 맵/시간 조합을 모두 제한 시간 내 낙하·위험 접촉 0회로 완주했습니다. 생존 확장 검사도 통과했습니다.
- 개발용 검증 화면에서 실제 이동·점프 물리를 빠르게 실행해 초원 1맵 47.87초 완주와 완주 카드를 확인했습니다. 위치를 순간 이동시키거나 기록 값을 직접 주입한 검사는 아닙니다. 사람이 전체 코스를 수동 완주한 결과와는 구분합니다.

아래 수동 브라우저·강의 연동·기기 크기 시험은 9월 13일 최초 검증 기록입니다. 9월 14일에 수정된 혼합 코스의 30개 연결 시험도 별도 서버에서 다시 실행했으며, 아래 부하 수치는 그 최신 결과입니다. 완주 시간과 빌드 크기도 수정본으로 갱신했습니다.

## 브라우저에서 직접 확인한 내용

제공된 브라우저 도구로 실제 웹 화면을 조작했습니다. 사용 가능한 브라우저는 Codex 내장 브라우저였으므로 **독립된 교사/학생 탭과 실제 WebSocket 접속**을 사용했습니다. Chrome와 Edge 두 엔진을 따로 실행해 시험한 것으로 표현하지 않습니다.

- 첫 초원 맵을 먼저 열어 로봇·배경·착지면·조작 화면을 확인한 뒤 나머지 맵을 추가했습니다.
- 이동 버튼 드래그와 키보드 점프로 실제 캐릭터가 이동하고 공중으로 뛰는 화면을 확인했습니다. 연습의 일시정지·계속하기가 동작했습니다.
- 교사 1명, 학생 하나/두리 2명으로 동일 방에 연결했습니다. 모두 준비한 뒤 같은 3초 카운트다운과 남은 시간을 받았습니다.
- 교사 화면에서 관전할 선수를 두리로 바꾸자 관전 표시가 바뀌었습니다.
- 경기 중 학생을 새로고침하고 “이전 참가방 다시 연결”을 눌러 남은 시간이 이어지는 화면을 확인했습니다.
- 학생 게임 모듈을 제거한 동안 교사 경기가 계속 진행했고, 재삽입·재접속이 성공했습니다.
- 교사 강제 종료와 시간 만료가 각각 다른 결과 문구로 표시됐습니다. 연결이 끊긴 학생은 선정에서 제외됐습니다.
- 첫 강의에서 결과가 “다음 활동 발표자: 하나, 두리”로 전달됐습니다.
- 두 번째 강의는 별도 생존 규칙으로 생성됐고, 세미/나루의 마지막 틱 동시 탈락을 공동 선정했습니다. 각각 3점이 표시됐으며 새로고침·기존 결과 재수신 후에도 3점으로 유지됐습니다. 첫 강의의 발표자 데이터와 섞이지 않았습니다.
- 재경기에서 이전 준비가 해제됐고, 최종 공장 맵·45초·꼴찌 선정 설정 적용을 확인했습니다.
- 844×390 가로 화면: 가로 넘침 없음, 이동 버튼 68×55px, 점프 버튼 92×55px. 390×844 세로 화면: 가로 넘침 없음. 화면 크기 변경은 브라우저의 viewport 시험이며 실제 휴대폰 시험이 아닙니다.
- 확인 시 브라우저 콘솔 오류가 없었습니다. 프레임 표시에서 60fps를 관찰했고, 여러 탭과 화면 캡처를 동시에 사용할 때 35~60fps 범위도 관찰했습니다. 지속적인 60fps를 보장하는 정식 기기 벤치마크는 아닙니다.

발견 후 수정한 문제: 짧은 점프 입력 누락, 빠른 화면 갱신에서 점프 보관 해제 시점, 재접속 정보에 메시지 타입이 섞이는 오류, 샘플 강의 프리셋 초기화, 학생 대기 화면 폭, 실행 직후 fps 표시, 온라인 캐릭터/발판 시계와 상대 위치 보간, 배포 방식 로컬 실행 시 Wi-Fi 주소 표시.

## 30개 연결 부하 시험

`npm run test:load`로 **실제 WebSocket 30개를 여는 개발용 봇**을 수정된 최종 공장 맵의 60초 경기(출발 카운트다운 3초 별도)에 참가시켰습니다. 화면에 봇 애니메이션만 표시한 시험이 아닙니다. 개발용 표시를 붙이고 사람용 선정 결과에서 제외했습니다. 9월 14일 재검사는 별도 3002번 서버에서 빌드된 코드로 진행했으며 최대 참가자는 30명이었습니다.

| 측정 | 값 |
|---|---:|
| 시험 소요 | 약 63.19초 |
| 테스트 접속 완주 | 30/30 |
| 오류 메시지 | 0 |
| 로컬 왕복 지연 중앙값 | 약 2.13ms |
| 로컬 왕복 지연 95백분위 | 약 6.10ms |
| 관찰된 서버 루프 최대 처리 시간 | 약 11.11ms |
| 수신 상태 메시지 | 39,466개 |
| 모든 테스트 연결의 수신 데이터 합계 | 약 422.47MB |

전체 측정은 `test-results/load.json`에 남겼습니다. 상태 전체를 JSON으로 20회/초 전송하는 현재 구현은 참가자가 늘수록 전송량도 늘어납니다. 실제 학교 Wi-Fi·휴대폰 30대에서의 지연, 전송량, 배터리, 발열은 별도 확인이 필요합니다. 현재 한 컴퓨터의 로컬 결과로 30명 실사용 성능을 보장하지 않습니다.

## 배포 파일 크기

마지막 빌드의 공통 게임 코드·스타일·맵·직접 그리는 그래픽은 약 81.66KB, gzip 기준 약 31.23KB였습니다. 복사해 사용하는 독립 ES 모듈은 약 103.62KB, gzip 기준 약 33.28KB입니다. 외부 그림이나 AI API를 런타임에 호출하지 않습니다. 서버 정적 응답에 gzip을 직접 적용하지는 않았으므로 gzip 크기는 압축 전송을 제공하는 배포 환경에서의 참고값입니다.

## 아직 확인하지 않은 항목

- 실제 Android/iPhone의 두 손가락 동시 터치, 화면 회전·전체화면 지원. 다중 포인터 논리는 자동 검사했고 브라우저 화면 크기를 바꿔 확인했으나 실제 기기 테스트는 하지 않았습니다.
- 실제 Chrome/Edge/Safari 조합, 실제 기기 30대 및 학교 네트워크, 멀리 떨어진 인터넷 환경의 입력 지연.
- 10개 코스를 사람이 각각 끝까지 조작한 숙련도·난이도 조사. 완주 가능성은 실제 공통 물리 자동 입력으로 확인했습니다.
- Render 계정 연결, 요금제 선택, 공개 배포, HTTPS/WSS 실서비스 운영. 배포 파일과 절차만 준비했습니다.
- 서버 재시작 뒤 방·결과 영구 복구, 다중 서버 운영, 학교 계정 인증. 현재는 메모리 방 + 결과 JSON/강의 어댑터 저장 방식입니다.
