# 루미 런 2.0 검증 기록

검증일: 2026-09-14. Windows / Node.js 24.16.0 / npm 11.13.0. 공개 배포가 아닌 로컬 제작·실행 검증입니다. 이전 1.x 검사는 `VERIFICATION-V1.md`에 보관했습니다.

## 자동 검사

- TypeScript 검사와 독립 화면·서버·ES 모듈 빌드 통과.
- 자동 검사 **22개 통과**: 참가자 시작, 30명 제한, 중복 시작·종료, 무제한 경기 시간, N명 완주, 첫 완주 때 꼴찌 선정, N번째 탈락, 경계 동점 공동 선정, 현재 위치와 최대 거리 구분, 무한/1/3/5 목숨, 재접속, 봇·끊김·관전자 제외, 물리와 입력, 압축 전송 보존, 가속 운반로 관성 등.
- **5개 맵 × 4가지 코스 길이 = 20개 조합 완주**, 낙하·위험 접촉 0회. 실제 공통 물리에 이동·점프·대기 버튼만 입력했습니다. 개발용 입력 도우미는 앞으로 착지 가능한지 같은 물리로 예측하고 기다릴 수 있으며 실제 플레이어의 위치·목숨을 조작하지 않습니다. 사람의 체감 난이도나 무실패 기록이라는 의미는 아닙니다.

| 맵 | 30초 코스 | 45초 코스 | 60초 코스 | 90초 코스 |
|---|---:|---:|---:|---:|
| 초원 | 22.45 | 36.73 | 47.10 | 71.28 |
| 공중정원 | 21.72 | 36.50 | 46.35 | 71.00 |
| 사막 | 21.93 | 36.70 | 46.60 | 71.22 |
| 수정동굴 | 22.52 | 37.88 | 47.85 | 73.07 |
| 별빛공장 | 21.30 | 33.50 | 43.55 | 65.55 |

단위는 실제 물리 자동 입력 완주 초입니다. ‘30·45·60·90초’ 옵션은 이제 코스 길이를 뜻합니다. 제한 시간이 아니므로 표시된 값과 실제 기록이 같을 필요는 없습니다. 공장은 가속 운반로를 정확하게 통과하면 더 빠릅니다.

## 실제 브라우저 확인

Codex 내장 브라우저의 독립 교사/학생 탭으로 확인했습니다. Chrome와 Edge 두 엔진 또는 실제 휴대폰으로 시험한 것은 아닙니다.

- 교사 방에 별빛하나·달빛두리로 참가했습니다. 학생의 ‘다 함께 시작’을 눌러 두 학생이 같은 카운트다운 뒤 출발했습니다.
- 두리가 이동하자 교사 화면이 ‘선두 · 달빛두리’로 바뀌고 하나 화면은 ‘별빛하나 · 목숨 무한’을 유지했습니다.
- 닉네임이 캐릭터 위에 보이고 전체 참가자 진행 표시가 두 사람을 함께 표시했습니다.
- 교사만 강제 종료 버튼이 보였으며 결과에 ‘교사가 종료’가 표시되었습니다.
- 외부 앱 설정 `participant:{id:'module-review-student',name:'앱에서온루미'}`를 주입한 모듈에서 이름 입력이 고정되고 실제 연습 캐릭터 머리 위에도 같은 닉네임이 표시되었습니다.
- 모바일 크기 390×844: 가로 회전 안내, 게임 조작, 세로 화면 배치를 시각 확인했습니다.
- 모바일 크기 844×390: 가로 시야와 이동 68×55px·점프 92×55px 버튼을 확인했습니다. 회전을 강제로 요구하지 않고 세로 조작도 유지합니다.
- 두 손가락 포인터 유지·해제·포커스 이탈은 자동 검사했습니다. 실제 휴대폰 멀티터치는 별도입니다.
- 검사 중 브라우저 콘솔 오류 0개. 두 학생 화면에서는 약 60fps 표시를 관찰했습니다.

## 실제 서버 연결 30개

빌드된 2.0 서버를 별도 3002번 포트에서 실행하고, **개발용 봇 30개가 각각 실제 WebSocket으로 접속**했습니다. 별빛공장 30초 코스·무한 목숨·30명 완주까지 진행했고 봇은 사람용 결과에서 제외했습니다. 실제 기기 30대 시험과는 구분합니다.

| 측정 | 결과 |
|---|---:|
| 접속 / 완주 | 30 / 30 |
| 서버 오류 메시지 | 0 |
| 시험 소요 (카운트다운 포함) | 약 25.24초 |
| 로컬 왕복 지연 중앙값 | 약 0.72ms |
| 로컬 왕복 지연 95백분위 | 약 6.06ms |
| 서버 루프 최대 처리 시간 | 약 8.66ms |
| 수신 상태 메시지 | 15,901개 |
| 전체 연결 수신 데이터 합계 | 약 82.66MB |

진행 중인 전송에서 반복되는 필드 이름과 변하지 않는 방·규칙을 줄였습니다. 같은 방의 메시지는 한 번만 직렬화해 공유합니다. 동일한 30명 상태의 전송 크기가 기존 전체 객체의 60% 미만인 것을 자동 검사했습니다. 이전 측정과 코스·종료 규칙이 달라 총 바이트를 직접 성능 개선 비율로 비교하지 않습니다.

## 30캐릭터 렌더 처리

1280×720 브라우저에서 동일 화면에 30캐릭터를 그렸습니다. 준비 20회를 제외한 120회의 동기 렌더 함수 시간을 측정했습니다. 기본 평균 약 8.73ms, 가벼운 그래픽 평균 약 8.22ms였습니다. 브라우저 스케줄링·일부 느린 표본의 영향을 포함합니다. 이 수치를 실제 화면 표시 간격이나 모바일 60fps 보장으로 환산하지 않습니다.

## 확인하지 못한 범위

실제 Android/iPhone 조합의 GPU·발열·배터리·두 손가락 입력, 30대 학교 Wi-Fi, 인터넷 지연, 저사양 휴대폰 지속 플레이는 아직 시험하지 않았습니다. 현재 로컬 시험은 통과했지만 **어떤 휴대폰 30대에서도 렉이 전혀 없다는 보장은 할 수 없습니다.** 가벼운 그래픽 옵션은 판정을 유지하고 배경·효과·해상도를 줄입니다.

Render 계정 연결·결제·공개 배포도 하지 않았습니다. 서버와 클라이언트가 같은 빌드로 실행되도록 준비했습니다. 서버 재시작 시 방과 결과는 초기화됩니다.

재현: `npm run check`, `npm test`, `npm run test:maps`, 개발 서버 실행 후 `npm run test:load`. 개발용 렌더·닉네임 검사는 `/scripts/mobile-review.html`이며 배포 빌드에 포함하지 않습니다. 원시 기록은 `test-results/maps.json`, `test-results/load.json`입니다.
